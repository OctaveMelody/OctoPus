13. JPS structure and conventions

JPS is ordinary text, normally stored with extension .jps. A score has a descriptive header followed by music Q: and lyrics C:. One Q line represents a printed music row; following C lines belong to that row. Numbered prefixes identify voices. A blank line ends the current system group and starts another; it is a structural separator, not just extra readability whitespace. A whole line beginning with # is a comment; inside a Q line, # is an accidental, not a comment.

The original specification calls V, B, D and P required fields. Include them for a complete portable score even though OctoPus tolerates incomplete drafts. Use uppercase header/prefix letters and the exact, case-sensitive lowercase literal [fenye]. Preserve the header/body distinction; repeated B/Z fields serve specific layout purposes. Unknown syntax may be preserved with diagnostics rather than rendered as intended.

Read a score in three passes

First read the header for title, key, meter and tempo. Then read only Q rows: digits and rests are musical events, suffixes modify their host, and barlines divide the flow. Finally read C rows and count lyric slots against the notes. The source order is also layout order: moving an entire Q row changes where music appears; moving its C row away may attach the words to a different row. Start the body with music, not unattached lyrics.

Plain JPS versus a saved document wrapper

A library .jps can be a JSON document whose code field contains the JPS and whose page_config field stores layout settings. Edit the code in JPS source, not the JSON punctuation. Downloadable manual excerpts are plain UTF-8 JPS for copying and opening. They carry musical headers and body text; to reproduce the pictured spacing exactly, open the named library sample so its page settings are restored.

Use a capital A-G key letter: C, F#, E$. Multiple B lines put subtitle text under the first title; multiple Z lines place credits at the upper right. P uses slash-separated numerator/denominator; spaces and parentheses can describe auxiliary meters. J may be numeric beats per minute, words, or a number followed by words; it prints on its own line at the left margin, below the key and meter. The spec defines X as a score sequence number, not a voice number; current OctoPus preserves X as header text but does not render it. Header values describe the score; a tempo field does not enable playback.

Required fields and repeated fields

For a complete score include V, B, D and P. V: 1.0 declares the syntax version; it is not the OctoPus application version. The first B is the centered main title and later B lines are centered subtitles. Each Z creates a separate right-aligned credit line. Optional J describes speed, and X can carry a catalog number. Keep these lines above the first Q. Empty or incomplete drafts may render, but do not rely on that as a portable document format.

Key, meter, tempo and comments

D: F# and D: E$ mean sharp and flat keys; use capital A-G and ASCII #/$, not full-width punctuation. P: 6/8 describes the meter; P: 4/4 (2/4 1/4) also lists auxiliary meters. It does not replace local barline meter changes. J: 90 prints the ♩= mark followed by the number, J: Allegro prints the words as they stand, and a number followed by words (J: 56 中速) prints the mark, the number and the words together on that same line. Words are printed as written and are not interpreted as a beats-per-minute value. A full line starting # is ignored as a source comment, whereas 4# inside Q is a sharp note. Quoted annotations are printed; source comments are not.

Header placement and a multilingual title

The second B is a subtitle; the three Z lines are separate credits. D: E$ displays the flat key. P sets 4/4 and J supplies a numeric tempo. The title punctuation is text, not a musical barline.
